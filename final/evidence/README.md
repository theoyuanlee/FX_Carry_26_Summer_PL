# `final/evidence/` — the committed results

**60 CSVs. Every number quoted anywhere in this package — the README, the verdict table, the eleven
report chapters — traces to one of them.** They are deliverables, not build artifacts: git-tracked
on purpose, and not to be deleted or regenerated casually.

This file is **self-contained on purpose**. In the multi-person repo the per-file descriptions lived
in Appendix A of `cesare/FX_Carry_Strategy_Project_Plan.md`, and this index only pointed at them so
the two could not drift. That was the right call there and the wrong one here: `final/` has to
survive `cesare/` being retired, and an index whose descriptions live in a folder that is going away
is an index that expires. So the descriptions are below. While both exist, the plan document's
Appendix A remains the fuller registry and the record of *why* each artifact was produced.

**Everything here is a byte-identical copy of `cesare/outputs/`** (verified by SHA-256 at vendoring;
re-checked by `../tests/test_vendor_drift.py`), except `component_verdicts.csv`, which is new and is
generated by `../verdicts.py`.

## How to read any number in here

Four conventions decide whether a figure means what you think it means.

1. **Gross and net are different columns, and only net is a result.** Costs are real per-currency
   bid/ask half-spreads, with maintained notional rolled via FX swap at the points spread rather
   than the outright. A Sharpe quoted without its cost drag is not a result.
2. **Two metric conventions coexist and must never be compared across.** `final_comparison.csv`
   labels them: `daily_net` (everything in the tradable book) and `monthly_uncosted` (D2 — monthly,
   on a 21-name option universe, gross of option bid/ask). Dropping D2's 1.69 Sharpe into the same
   column as a costed daily book would manufacture exactly the false comparability the label
   prevents.
3. **Annualised ratios are blank under 120 trading days, and that is deliberate.** Annualising a
   Sharpe off 64 days of COVID is noise wearing a decimal point. Short windows report cumulative
   return, MaxDD, worst day and `n_days` instead. `episodes.report_windows` enforces it.
4. **Rows that do not reconcile to the shared base are kept and flagged** `on_base=False`, never
   dropped. A teammate's book disagreeing with the base *is* the finding.

**Three unit traps**, each of which has bitten once:

- `p3_d1_bkm_spanning.csv` stores `alpha_ann` as a **decimal** (`0.032172` = 3.22%/yr);
  `p3_d2_spanning.csv` stores it as a **percent** (`3.334531` = 3.33%/yr). No published number is
  wrong, but any chart combining the two is off by 100×. Left as-is rather than silently
  renormalised — changing a committed CSV's units to fix a documentation problem is how a
  reconciliation breaks.
- `p4_combined_ladder.csv`'s `survivors` column reads `duration|vix_gate|skew_excl` (three names) on
  every row while the shipped book has **two**. Not a contradiction: `survivors` is the set that
  passed a **Sharpe-sign** filter and therefore entered the `final` re-ladder, whereas `ADOPTED` is
  the set that earned a **slot** in it. The VIX gate passes the first and fails the second — which
  is the whole of the contested verdict in `../VERDICTS.md`.
- `p4_tail_forecast_eval.csv`'s mean OOS AUC of 0.4685 averages the **6 folds where AUC is defined**,
  not all 13. Seven folds contain no tail month at all.
